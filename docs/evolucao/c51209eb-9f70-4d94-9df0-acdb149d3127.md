## Plano da Celeste

Olá! Sou a Celeste e preparei este plano para implementarmos a funcionalidade de verificação e atualização forçada do aplicativo sempre que houver um novo merge/deploy no GitHub. 

Este é apenas um plano detalhado de como poderemos executar essa melhoria:

---

### 1) Objetivo
Garantir que os usuários sempre utilizem a versão mais recente da aplicação React. O sistema detectará automaticamente quando um novo código for integrado no GitHub e exibirá uma notificação ou botão para atualizar a página, limpando caches antigos de forma segura.

---

### 2) Etapas numeradas

1. **Injeção de Versão no Build:**
   * Configurar o script de build do React para gerar um arquivo estático leve (`version.json`) ou injetar uma variável de ambiente (`VITE_APP_VERSION`) contendo o hash do commit do GitHub ou o timestamp do deploy.

2. **Criação do Endpoint de Checagem (Cloudflare Worker ou Arquivo Estático):**
   * Disponibilizar o arquivo `version.json` na raiz da publicação ou criar uma rota rápida no Cloudflare Worker que retorne a versão mais recente em execução.

3. **Criação do Hook de Verificação (React / TanStack Query):**
   * Desenvolver um custom hook no React (ex: `useVersionCheck`) usando TanStack Query para consultar o endpoint de versão em intervalos regulares (ex: a cada 5 ou 10 minutos) e ao focar a aba do navegador (`refetchOnWindowFocus`).

4. **Desenvolvimento da Interface (Botão / Banner de Atualização):**
   * Criar um componente visual discreto (banner no topo ou notificação Toast) alertando: *"Uma nova versão está disponível!"* com o botão *"Atualizar Agora"*.

5. **Lógica de Recarregamento e Limpeza de Cache:**
   * Ao clicar no botão, disparar a desregistração/atualização do Service Worker (se houver PWA), limpar caches do navegador (`caches.delete`) e forçar a recarga da página (`window.location.reload()`).

---

### 3) Telas e partes afetadas

* **Frontend (React / TanStack):**
  * Componente Global de Notificação/Toast (visível em todas as telas).
  * Custom Hook `useVersionCheck`.
  * Arquivos de configuração de PWA / Service Worker (se aplicável).
* **Servidor de IA / Middleware (Cloudflare Worker):**
  * Rota opcional para consultar versão atual do backend/frontend, se necessário.
* **Pipeline CI/CD (GitHub Actions / Deploy):**
  * Processo de build ajustado para salvar o hash do commit no momento da compilação.

---

### 4) Serviços/APIs externas necessárias

* **GitHub / GitHub Actions:**
  * *Status:* Gratuito (respeitando os limites padrões de minutos da plataforma).
  * *Chave/Configuração:* Não exige chaves pagas extras, apenas acesso às variáveis padrão do pipeline (ex: `GITHUB_SHA`).
* **Cloudflare Workers:**
  * *Status:* Possui plano gratuito (com limite de requisições diárias mais que suficiente para checagens de versão).
  * *Chave/Configuração:* Requer token de autenticação de API do Cloudflare para automação de deploy, caso utilizado como intermediário.
* **APIs Nativas do Navegador (Cache Storage & Service Worker API):**
  * *Status:* Gratuitas e nativas de todos os navegadores modernos (sem chaves).

---
